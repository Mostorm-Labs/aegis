## What beta.3 is

Beta.3 reduces redundant proof work in the Aegis evidence-driven lifecycle without weakening Gate safety. It introduces a failure-mode-first rule for deciding which Evidence Artifacts are allowed to block lifecycle progression.

## Changes since beta.2

- Adds the **Blocking Evidence Necessity Invariant**: an Evidence Artifact may become a blocking Gate requirement only when its absence leaves at least one high-impact failure mode without credible independent detection coverage.
- Adds the balancing rule `Missing Evidence != Automatically Gate Blocked` while retaining `Code Complete != Gate Complete`.
- Changes P20 Verification Design to start from failure modes, existing independent coverage, and the residual proof gap before choosing evidence.
- Requires independence to be assessed at the detection-mechanism and oracle level; duplicate execution locations or tests sharing the same oracle do not count as independent coverage.
- Changes P34/P35 so `EVIDENCE_GAP` means a residual proof-capability gap rather than checklist or named-artifact incompleteness alone.
- Preserves fail-closed identity, provenance, materialization, and reviewer-accessibility requirements when those requirements are themselves necessary to close a high-impact proof gap.
- Adds regression coverage that protects the policy and canonical-to-Plugin materialization parity.

## Product effect

Aegis should now ask a stricter question before adding blocking evidence: **what high-impact failure mode becomes credibly undetectable if this evidence is absent?** If there is no residual independent coverage gap, additional confidence, diagnostic, audit, or observability evidence remains useful but non-blocking.

This reduces evidence-for-evidence's-sake while keeping high-impact failure detection and formal Gate ownership intact.

## Distribution and verification

The prerelease publishes an exact-nine Aegis Plugin Installation Kit, release manifest, and SHA-256 checksums. The release workflow revalidates Project State, deterministic Skillset generation, distribution contracts, routing, installed-platform state, generated Skill structure, and repository regressions before publication.

## Upgrade / rollback

Use a whole-catalog Plugin transition or the published beta.3 Installation Kit. Roll back to immutable `v0.2.0-beta.2` if the new blocking-evidence policy causes unexpected routing or Gate-review behavior in an existing project.
